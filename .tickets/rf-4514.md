# Upload the clipboard image (screenshots): r2fl up --clipboard

## Why
The most common thing to share with an agent is a screenshot. Saving it to a file first is friction; `r2fl up --clipboard` (or `r2fl clip`) should upload the image currently on the clipboard.

## Design

- macOS: there is no built-in CLI to read image data from the clipboard. Options: use `osascript -l JavaScript`/AppleScript (`the clipboard as <<class PNGf>>`) to write PNG bytes to a temp file, or detect `pngpaste` if installed. Prefer zero extra dependencies; fall back to `pngpaste` if AppleScript is unreliable. Linux: `wl-paste --type image/png` (Wayland) or `xclip -selection clipboard -t image/png -o` (X11).
- If the clipboard has text instead of an image, upload it as text/plain (name `clipboard.txt`) behind an explicit flag only; default to an error to avoid accidentally publishing text (passwords!).
- Temp files go in the OS temp dir with mode 600 and are deleted in a `finally`.
- Name files `screenshot-<timestamp>.png`; reuse the normal upload path (size cap, ttl, history, clipboard copy of the URL).
- Read the clipboard through an injectable function so tests don't need a real clipboard.

## Acceptance Criteria

- [ ] `r2fl up --clipboard` uploads the clipboard image on macOS and on Linux (Wayland and X11) when the tool is available; clear error when no image/tool is present.
- [ ] Text clipboard content is NOT uploaded unless an explicit flag is given.
- [ ] Temp files are removed on success and failure; verified by a test with an injected reader.
- [ ] Documented in README; works with `--ttl`, `--max-downloads`, `--json`.
